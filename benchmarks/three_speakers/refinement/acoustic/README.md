# Verifying a third voice in complete Mandarin meetings

The verifier processes one mono room microphone. It builds a small spectral dictionary for each of the three speaker slots from confidently predicted solo turns. For a suspected overlap, matching pursuit reconstructs the spectrum with all three dictionaries and with each speaker’s dictionary left out in turn. The residuals estimate how much each voice contributes. A lightweight classifier combines this acoustic evidence with the relative strengths and time variation of the two Nemotron passes.

The 37:19 development recording R8008_M8013 determines the classifier and its operating point. Four folds hold out interleaved 30-second development intervals and exclude one second near interval boundaries from training. The decoder selects separate thresholds for retaining a proposed triple and promoting an existing pair. Only thresholds that preserve development precision, retain at least 82% of the previous exact-three recall, and meet a 0.2 percentage point overall DER tolerance are eligible. The development score is out-of-fold for the classifier. Threshold choice, feature design and the original calibrated decoder share the same development meeting. A symmetric threshold failed these checks.

On R8008_M8014 and R8008_M8015 together, false three-voice declarations dropped from 22.56 to 19.68 seconds. Exact-three F1 rose from 25.87% to 27.64%, and overall DER fell from 11.00% to 10.92%. Three-way speaker-time recall fell from 86.82% to 86.30%. Exact-three precision was 17.93% and exact-three recall was 60.31%. There were 7.13 seconds of reference triple overlap in 63:53 of these meetings. The two mono inference passes are required before the additional file-level verification. The dictionary approach uses file-wide speaker enrollment.

Set `PYTHONPATH` to include the enclosing repository's `benchmarks/three_speakers/target_90` and `benchmarks/three_speakers`. The `--work` and `--views` directories use the cache layout described by the previous long-meeting experiments. They contain the 37-minute development mono WAV, the first-pass posteriors and RTTM, and the second-pass posteriors generated by `prepare_mono_view.py` with a 9.28-second lead-in and the previous benchmark’s native C++ runner. Run with two CPU threads.

```bash
python verify_long.py --work /path/to/previous --views /path/to/shifted --output results.json
python neural_probe.py --work /path/to/previous --views /path/to/shifted --cache /path/to/empty-probe-cache --output neural.json
python new_recording.py --work /path/to/previous --views /path/to/shifted --input-dir /path/to/additional-meeting --out /path/to/timing
```

For a new meeting, the input folder contains `mono.wav` at 16 kHz, `native.rttm`, `probabilities.npz`, and `view.npz`. This command fits on the original development meeting, uses those four inputs to export A/B/C timings, and accepts an optional `--score` switch for folders containing a separate `reference.rttm`. The independent Sortformer experiment uses the project's original Sortformer v2 ONNX file and local adapter in the work folder. It runs the pretrained model on packed uncertain intervals with context and puts automatically located solo examples at the start. The Sortformer fit and timing checks use the same development/holdout split.

## Apply the frozen model

For a folder containing a new meeting’s mono WAV, native RTTM, and two posterior archives, use the distributed `dictionary_model.json`. Its 70 numeric trees, 42-feature schema size, thresholds, and prior decoder profile fit in 42 KiB.

```bash
python new_recording.py --frozen dictionary_model.json --input-dir /path/to/meeting --out /path/to/output
```

This command emits A/B/C timing JSON without downloading any development recordings or fitting a classifier. On all 5,260 candidate frames of the fresh 30:39 recording R8008_M8016, the portable decoder’s probabilities matched scikit-learn exactly. The resulting timing and score files matched byte for byte. The trained and portable models use the same per-meeting acoustic enrollment from the input audio. The development fit can also be regenerated using the original `--work` and `--views` arguments plus `--save-frozen PATH`.
